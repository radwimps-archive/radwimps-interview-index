# RADWIMPS Archive

RADWIMPS とメンバーのインタビュー・対談・ライブレポートを、人・曲や作品・年代・ライブから探せる索引サイトです。
記事の本文は載せず、タイトル・掲載日・媒体名・短い説明と、掲載元へのリンクをまとめています。

- 公開サイト：https://radwimps-archive.github.io/radwimps-interview-index/
- **運用マニュアル：[docs/manual.md](docs/manual.md)**（公開のしかた・記事の追加・リンク切れへの対応）
- 記事データ作成ツール：公開サイトの `maker.html`

## できること

- 4つの入口（人から探す・曲・作品から探す・年代から探す・ライブから探す）で記事一覧を絞り込み。ライブレポートは公演日ごとにまとめて表示
- 種類のタブ（記事・資料／動画インタビュー／リリース情報／すべて）と、「さらに絞り込む」（内容・人物・年代・掲載メディア・言語・資料の種類・読書の状態）
- タイトル・人名・作品名・説明での検索（ひらがな・カタカナ・ローマ字でも探せます）。「ランダムに読む」も
- 記事はカードで12件ずつ表示（YouTube の動画にはサムネイル付き）。「説明を開く」で説明・メモ・タグ
- あとで読む・既読の記録（見る人のブラウザに保存。「保存データの管理」からファイルにバックアップも可）
- 絞り込みの状態は URL に入るので、そのまま共有できます（例：`?person=野田洋次郎`）
- 運営管理（URL の末尾に `#admin`）から、記事の追加・修正・非表示・削除をして、そのまま GitHub に保存（最初に一度だけ、GitHub で「合鍵」＝アクセストークンを作って登録）

## 記事を追加・修正するには

- **運営管理から**：記事を追加・修正して「GitHub に保存」を押します（準備はマニュアルの「[9. あとで読む・既読と運営管理](docs/manual.md#9-あとで読む既読と運営管理)」）。
- **GitHub の画面から**：`data/articles.csv` を書き換えて保存（コミット）します（「[3. 記事を追加する](docs/manual.md#3-記事を追加する)」）。

どちらも1〜2分でサイトに反映されます。

## 自動で動くもの（GitHub Actions）

| ワークフロー | いつ | すること |
|---|---|---|
| サイトを公開する | `main` に保存したとき | 記事データの書式をチェックし、問題なければ GitHub Pages に公開。問題があれば公開を止めて通知 |
| リンク切れチェック | 毎週月曜 9:17ごろ（日本時間） | 全記事のリンクを確認し、対応が必要な記事を Issue でお知らせ |

## ファイル構成

```
index.html            サイトの骨組みと文章
maker.html            記事データ作成ツール
history.html          「RADWIMPSの歩み」（年表）のページ
assets/
  style.css           見た目（色など）
  app.js              画面の動き（探す入口・検索・絞り込み・あとで読む・既読）
  history.js          「RADWIMPSの歩み」（年表）の動き
  admin.js            運営管理の「記事の管理」（記事の編集と GitHub への保存。運営管理を開いたときだけ読み込み）
  ui.js               画面の共通部品（メニュー・管理者モード・ファイルの書き出しなど。3つの画面で共通）
  data.js             CSV の読み方と「書ける値」の決まり（記事・年表）、「曲・作品から探す」の作品の一覧（サイトとチェック用プログラムで共通。画面の処理は入れない）
  config.js           設定（独自ドメインのとき・タワーレコードのアフィリエイトを始めるとき）
  icon.svg            ブラウザのタブのアイコン
data/
  articles.csv        記事の一覧
  releases.csv        年ごとの主なリリース（「年代から探す」で年を選ぶと出る）
  history.csv         「RADWIMPSの歩み」（年表）の出来事
tools/
  validate.mjs        書式チェック（記事・年ごとのリリース・年表）
  check-links.mjs     リンク確認
tests/
  data.test.mjs       data.js（CSV の読み取り）のテスト
.github/workflows/    自動公開・自動チェックの設定
docs/manual.md        運用マニュアル
```

ビルドの手順や `npm install` は必要ありません。ファイルはそのまま公開されます。
チェック用プログラムとテストは Node.js だけで動きます（`node tools/validate.mjs`、`node --test`）。
`assets` に新しいファイルを足すときは、名前を小文字の英字だけにします（例：`ui.js`）。公開時に古いファイルが残らないようにする仕組み（`.github/workflows/deploy.yml`）が、その形の名前にだけ効くためです。

## 合鍵（アクセストークン）について

運営管理で使う合鍵は、登録した端末のブラウザ（localStorage）にだけ保存され、GitHub（api.github.com）以外には送られません。合鍵には、このリポジトリの「Contents」の読み書きだけを許可してください。

## 権利について

記事の本文・タイトルの権利は、各媒体と取材者にあります。この索引はリンク集として運営しています。
